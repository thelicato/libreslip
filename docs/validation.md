# Release candidate validation

Validated on 25 September 2026 for LibreSlip 0.14.0, Android application identifier `io.thelicato.libreslip`.

| Check | Result |
| --- | --- |
| Dart formatting | Passed across application, test and integration-test Dart sources. |
| Static analysis | Passed with no issues. |
| Unit and widget tests | All 90 active tests passed; the normal run skipped only the opt-in render capture. |
| Port 5119 default | Passed the shared protocol constant used by the foreground HTTPS listener and Client address normalisation. An address without a port resolves to 5119, while an explicitly supplied valid port is retained. Every user hint, preview endpoint, fake host and Android integration endpoint uses 5119. |
| Paired-destination migration | Passed schema 9 upgrade of stored LibreSlip URLs ending in port 42837 to 5119. A stored destination using custom port 6000 remained unchanged. Certificate fingerprints, access tokens, outbox envelopes and protocol version are not rewritten. |
| Item-total calculation | Passed all-history, empty and inclusive local start/end date ranges. Totals use immutable saved-ticket snapshots, sum quantities, and keep renamed snapshot labels distinct. No current catalogue edit can rewrite them. |
| Item-total dialog | Passed single-item and nine-item phone tests, including a complete scrollable list, localised integer formatting, empty-state support, accessibility summaries and bounded dialog layout. |
| HTTPS and delivery regression | Passed real loopback TLS pairing with the generated self-signed Server identity, strict SHA-256 certificate pinning, authenticated delivery, lost-acknowledgement retry and idempotent Server receipt. A mismatched certificate remained rejected. |
| Backup compatibility | Passed configuration and full-backup round trips, fresh-install restore, rollback and malicious archive checks for portable schema 9. Full backups retain the item delivery flag; legacy schema 5, 6, 7 and 8 snapshots remain accepted. Networking tables and pairing secrets remain excluded until Task 15. |
| Accessibility and localisation | Passed British English and Italian phone, landscape, tablet and doubled-text tests. The item-total action, title, description and empty state are localised. |
| Representative renders | Thirteen fresh previews completed without framework errors. The English item-total phone dialog was visually inspected: title, explanation, rows, quantities, scrolling bounds and close action are aligned, unclipped and readable. Existing Client, Server, Overview, Compose, item, ticket, Settings and portability renders also completed. |
| Android platform integration | Not repeated because the emulator remains stopped and no Android device is connected. The integration source now uses port 5119. The preceding Android 14 run passed real DataStore, SQLite, secure identity and token storage, pinned loopback delivery, listener shutdown, restart recovery and archive exclusion. Schema 9 migration is covered by host SQLite tests. |
| Offline cold launch | Not repeated because no Android device is connected. The Task 12 development-signed release passed clean offline cold launch on Android 14. |
| Release APK | Passed with the temporary development validation certificate. Verified version 0.14.0, application identifier `io.thelicato.libreslip`, minimum API 34, target API 36 and APK Signature Scheme v2. Flutter and Gradle APK outputs matched byte for byte. |
| Permissions and backup | The release requests `BLUETOOTH_CONNECT`, `INTERNET` and Android's app-local dynamic-receiver signature permission. It requests no location or broad storage permission. `INTERNET` permits optional LAN sockets and does not make core Client operation depend on the internet. Automatic cloud backup and device transfer remain disabled. |
| Physical NETUM NT-1809DD | The user's Task 4 report confirms Bluetooth printing on the physical printer. Physical printing was not repeated for this Overview and networking-port milestone. Battery percentage remains unavailable because neither the printer documentation nor Android's public Classic socket API provides it. |
| Delivery artefacts | The source ZIP uses a `LibreSlip/` root and excludes caches, build state, SDK paths, signing material and previous archives. The development-signed preview APK and both-file SHA-256 list are generated by the stale-APK guarded packager. |

Task 14 changes the fixed LAN endpoint and improves visibility of statistics without changing order contents, printing or protocol version 1. Physical communication between two separate Android devices on the same Wi-Fi network remains unverified. Router client isolation, network changes, multiple physical clients, mDNS evaluation, networking-data backup policy, larger-queue hardening and any decision about foreground-service hosting remain Task 15.

Existing paired Clients are migrated to port 5119 at database open. A Client that was deliberately paired to a non-standard port remains on that port. External firewall or router rules must allow device-to-device TCP 5119 for optional Server delivery.

The Android document picker and share-sheet interaction were compiled into the release APK but were not manually repeated during Task 14. Export cancellation and destination behaviour remain platform-owned and unobserved here. The GitHub release workflow was not executed because no tag was pushed and no repository secrets were changed.

The physical printer result is user-reported evidence from Task 4. A transmitted printer state still means that the phone completed its socket write, not that LibreSlip can prove paper output. The app never automatically retries an uncertain print. USB printing remains outside the current implementation.

The preview APK uses a development validation certificate and is not a production upgrade baseline. The repository owner must keep the long-lived release keystore securely backed up, configure the documented GitHub secrets, and publish only from a matching `v0.14.0` tag.
